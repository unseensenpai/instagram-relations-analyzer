# v1.1.0 — 2026-08-20

Multilingual support, in-list search, a reworked export panel, and several
reliability fixes for syncing large profiles.

## Added

### Multilingual interface (English / Turkish / Spanish)
The entire panel is now translated. The language is auto-detected from the
browser on first use and can be changed at any time from the sidebar; the
choice is remembered across sessions. Exported CSV headers and section titles
follow the selected language as well.

### Search within the open list
A search box above the list filters the current view by username or full name
as you type. Matching is accent- and case-insensitive using locale-aware
comparison, so Turkish characters such as `İ` and `ı` behave correctly.
Search affects the view only — exports always contain the full list.

### Progress feedback during sync
Syncing now reports what it is doing at every stage instead of showing a
single static message:

- `Fetching Followers... 275 / 430 (64%) — about ~25s left`
- `Comparing lists...`
- `Saving results...`
- `Preparing list (464 users)...`

Totals are read from the profile header when available; if they cannot be
read, the counter still shows how many users have been fetched so far.

### Export moved to the sidebar
Each list now has its own `↓` button, so it is always clear which list is
being downloaded. A **Download All** button exports all four lists at once,
and a single format selector (Excel/CSV or JSON) applies to both. Download
buttons are disabled for empty lists.

**Full profile export is now available in CSV**, not just JSON — previously
only `Full Profile Data (JSON)` existed.

## Fixed

### Sync silently failed on large profiles
Results were written to `localStorage` as the raw API response, including
long `profile_pic_url` fields for every user. On profiles with several
hundred connections this exceeded the browser's ~5 MB storage quota and threw
`QuotaExceededError`, which was never caught: the sync stopped without a
message, counters stayed at `0`, and nothing was saved.

Cached entries now store only `pk`, `username` and `full_name`, cutting the
payload by roughly 90%. If the quota is still exceeded, other profiles'
caches are pruned and the write is retried; if that also fails, the list is
still rendered on screen and a clear warning explains that it will not
persist.

### Errors during fetch were swallowed
Network failures, rate limits (HTTP 429) and malformed responses were caught
and logged to the console, then the loop exited quietly with whatever partial
data had been collected — and that partial data was saved to the cache as if
the sync had succeeded.

Every failure path now stops the sync, reports a specific message on screen,
and leaves the previous cache untouched.

### Cached data was not shown when reopening the panel
The floating button had two independent click listeners — one in
`content.js` toggling the panel, one in `modal.js` loading the data — with no
guaranteed ordering between them. The panel now observes the overlay's
visibility directly, so cached data is loaded reliably every time it opens.

### A cancelled sync destroyed existing data
The cache was cleared as soon as a sync started. If the sync was then
interrupted — by a page refresh, an SPA navigation, or an error — both the
new and the previously saved data were lost. Existing data is now kept until
a sync completes successfully.

## Changed

- The panel warns before closing while a sync is in progress.
- List rendering uses a `DocumentFragment`, reducing layout work on lists
  with hundreds of entries.
- User names are inserted with `textContent` instead of `innerHTML`,
  eliminating an injection risk from profile display names.
- Outbound profile links now carry `rel="noopener noreferrer"`.

## Notes

The 1.5-second delay between pagination requests is unchanged. It exists to
avoid Instagram's rate limits and should not be reduced — a profile with 500
followers takes roughly 1–2 minutes to sync.
